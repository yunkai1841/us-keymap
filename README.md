# UsKeyBridge

Windows のキーボード設定が日本語配列 (JIS) のまま変更できない PC で、**US 配列の外付けキーボード**を
US 配列どおりに使えるようにする常駐ツールです。

- 外付けの US 配列キーボード → 刻印どおりの記号が入力される (`Shift+2` で `@`、`[` `]` `\` `'` `` ` `` など)
- ノート PC 内蔵の日本語配列キーボード → これまでどおり (変換しない)
- どちらのキーボードから入力されたかを自動で判別します
- 管理者権限もインストールも不要。Windows に標準で入っている C# コンパイラでビルドします

## ビルド

`build.bat` をダブルクリックします。

```
[1/3] Building bin\UsKeyBridge.exe ...
[2/3] Building bin\EngineTests.exe ...
[3/3] Running tests ...
NN passed, 0 failed
Done: bin\UsKeyBridge.exe
```

`0 failed` で終わればビルド完了です。`bin\UsKeyBridge.exe` ができます。

> 必要なのは `C:\Windows\Microsoft.NET\Framework64\v4.0.30319\csc.exe` (Windows 10/11 に標準で入っています) だけです。

## 使い方

1. `bin\UsKeyBridge.exe` を起動すると、通知領域 (タスクトレイ) に青い **US** アイコンが出ます。
2. 外付けキーボードで記号を入力してみてください。
3. アイコンの操作
   - **左クリック**: 有効 / 無効の切り替え (無効のときはアイコンが灰色)
   - **右クリック**: メニュー

### メニュー

| 項目 | 内容 |
|---|---|
| 有効 | 変換のオン/オフ |
| 判別モード | 「キーボードごとに判別する (推奨)」または「すべてのキーボードを US 配列として扱う」 |
| US 配列として扱うキーボード | 接続中のキーボードの一覧。チェックが付いているものを US 配列として扱います。クリックで切り替え |
| US 配列キーボードの CapsLock を CapsLock として使う | 日本語配列では CapsLock キーが「英数」になるため、US 配列キーボードの CapsLock を本来の CapsLock にします |
| 状態を表示 | 判別の状況や、最後に入力したキーボードなどを表示 |
| 診断ログを記録する | うまく動かないときの調査用 |
| Windows の起動時に自動で起動する | ログオン時に自動起動します (HKCU の Run に登録) |

### キーボードの判別

設定していないキーボードは自動で判定します。

- **USB / Bluetooth 接続** → US 配列として扱う
- **内蔵 (PS/2)、その他** → 日本語配列として扱う

違っている場合は「US 配列として扱うキーボード」でクリックして切り替えてください。外付けキーボードで何か入力してからメニューを開くと、そのキーボードに「← 最後に入力したキーボード」と表示されるので見分けられます。

記号キーがどちらのキーボードから来たかは、**直前に使われたキーボード** (文字キーや Shift の入力元) で判断します。
`Shift+2` なら先に押した Shift で判別できるので、ふつうに打っていれば正しく変換されます。
ただし、キーボードを持ち替えて**最初の 1 打鍵が修飾キーなしの記号** (`[` `'` など) だと、
前のキーボードとして扱われることがあります (2 打鍵目からは正しくなります)。

## 変換の内容

修飾キーなし、または Shift だけを押しているとき (文字として変換):

| US 配列のキー | 入力される文字 |
|---|---|
| `` ` `` / `` Shift+` `` | `` ` `` / `~` |
| `Shift+2` | `@` |
| `Shift+6` | `^` |
| `Shift+7` / `8` / `9` / `0` | `&` / `*` / `(` / `)` |
| `Shift+-` | `_` |
| `=` / `Shift+=` | `=` / `+` |
| `[` `]` / `Shift` 付き | `[` `]` / `{` `}` |
| `\` / `Shift+\` | `\` / `\|` |
| `Shift+;` | `:` |
| `'` / `Shift+'` | `'` / `"` |

上の表にないキー (英字、数字、`,` `.` `/` など) はどちらの配列でも同じなので、そのまま通します。

**Ctrl / Alt / Win と同時に押したとき**は、US 配列の PC と同じ仮想キーコードになるように変換します。
たとえば VS Code の `` Ctrl+` `` (ターミナル)、ブラウザーの `Ctrl+=` (拡大) などが US 配列と同じように動きます。

**IME のオン/オフ**: US 配列キーボードでは `` Alt+` `` で切り替えます (日本語配列の `Alt+半角/全角` として送ります)。

IME を英語 (US 配列のレイアウト) に切り替えているときは変換しません (二重に変換しないため)。

## うまく動かないとき

1. **「状態を表示」を開く**
   - 「受け取った Raw Input」が増えていれば、キーボードの判別は動いています。
   - 0 のままの場合、この PC ではキーボードの入力元が分かりません。
     「判別モード」→「すべてのキーボードを US 配列として扱う」に切り替えてください
     (この場合、内蔵キーボードも US 配列として扱われます)。
   - 「最後に入力したキーボード」が外付けキーボードになっているかも確認してください。
2. **外付けキーボードが US 配列として扱われていない**
   - 「US 配列として扱うキーボード」でチェックを付けてください。
3. **診断ログ**
   - 「診断ログを記録する」をオンにして少し入力し、「ログフォルダを開く」で `debug.log` を確認します
     (`%LOCALAPPDATA%\UsKeyBridge\debug.log`)。**入力したキーがすべて記録される**ので、
     パスワードなどを入力する前にオフにし、調査が終わったら削除してください。

## 制限事項

- **管理者権限で動いているウィンドウ** (タスクマネージャー、管理者として実行したアプリなど) では変換されません。
  必要な場合は UsKeyBridge も「管理者として実行」してください。
- **サインイン画面・ロック画面・UAC の確認画面**では変換されません。
  ここで US 配列キーボードを使うと日本語配列として入力されるので、**記号を含むパスワードに注意**してください。
- キーボードフックを使うため、セキュリティソフトがキーロガーとして警告することがあります。
  会社の PC では社内のルールに従ってください。
- キーボードごとの判別には、Windows の低レベルキーボードフック (キーを書き換える) と
  Raw Input (入力元のキーボードが分かる) を組み合わせています。
  フックで止めたキーには Raw Input が届かない環境があるため、止めずに通したキーの Raw Input から
  「直前に使われたキーボード」を覚えて判断しています。

## アンインストール

1. メニューの「Windows の起動時に自動で起動する」をオフにする
2. メニューの「終了」
3. このフォルダを削除
4. 設定を消す場合はレジストリの `HKEY_CURRENT_USER\Software\UsKeyBridge` を削除

## ファイル構成

```
build.bat            ビルド (テストも実行)
src/
  Program.cs         エントリポイント (多重起動防止)
  TrayApp.cs         トレイアイコンとメニュー
  Bridge.cs          キーボードフック / Raw Input / SendInput
  Engine.cs          変換エンジン (キーボードの判別と順序の保持)
  KeyMap.cs          US 配列 → 日本語配列の対応表
  Devices.cs         キーボードの一覧と US/JIS の判定
  Settings.cs        設定の保存 (HKCU\Software\UsKeyBridge)
  Native.cs          Win32 API の宣言
tests/
  EngineTests.cs     変換エンジンの単体テスト
```
